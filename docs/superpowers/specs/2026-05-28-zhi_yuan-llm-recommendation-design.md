> 创建日期：2026-05-28
> 版本：v1.0
> 方案：结构化引擎 + LLM增强层（方案A）

## 1. 产品定位

**一句话定位**：基于全维度用户画像 + 结构化数据引擎 + LLM智能解读的高考志愿填报助手，不仅帮考生找到"能上的学校"，更帮他们找到"适合的路"。

**目标用户**：C端考生及家长

**产品形态**：Web网站（后续可扩展小程序/App）

**商业模式**：免费基础功能 + 增值付费

**差异化**：用AI把"万元级人工咨询"的深度，做到"百元级产品"的价格。

## 2. 用户画像 · 五维输入模型

### 2.1 维度定义

| 维度 | 包含字段 | 采集方式 |
|------|---------|---------|
| **基础信息** | 高考分数、省排名（位次）、所在省份/城市、科类（文/理/新高考选科组合）、体检限制（色盲色弱、身高视力等） | 必填表单 |
| **家庭维度** | 家庭年收入区间、家长职业/行业背景、可承担学费区间（含中外合办/民办接受度）、家庭所在地 vs 期望就业地、家庭资源与人脉方向 | 选填表单 |
| **性格维度** | MBTI/霍兰德职业兴趣（内置简化测评）、兴趣爱好（运动/艺术/技术/阅读/社交活动等）、内向/外向倾向、抗压能力/风险偏好 | 测评+标签 |
| **能力维度** | 学科强项（哪几科明显突出）、社交能力自评（沟通/领导/团队协作）、动手能力/实践能力、英语/外语水平、竞赛/特长/获奖经历 | 选填表单 |
| **价值观维度** | 职业价值观（高薪/稳定/社会价值/自由/创造力）、是否接受外地求学（距离偏好）、未来规划倾向（考研/出国/直接就业/考公）、行业偏好（互联网/金融/医疗/教育/体制内等）、生活态度（工作生活平衡 vs 拼搏优先） | 选填表单+滑块 |

### 2.2 渐进式采集流程

采用渐进式策略，避免一次性表单吓退用户：

**Step 1 · 核心输入（必填，30秒）**
- 分数 + 位次 + 省份 + 科类
- 即刻生成"能上哪些学校"基础推荐

**Step 2 · 快速画像（引导填写，2分钟）**
- 兴趣偏好（点选标签，如"喜欢计算机""想去一线城市"）
- 是否接受外地 + 学费接受范围
- 推荐结果精炼，加入适配度评分

**Step 3 · 深度测评（可选，10-15分钟）**
- 内置简化版霍兰德 + MBTI测评
- 家庭背景 + 能力自评 + 价值观
- 解锁"专业适配分析""职业路径推荐"等深度功能

**设计原则**：
- 每完成一步，用户立刻能看到有价值的输出（不等全部填完才给结果）
- Step 1 是免费功能入口，Step 2-3 的填写引导付费解锁
- 性格/能力/价值观通过标签点选 + 滑块评分完成，不要求写大段文字
- LLM在后续对话中可补充追问，动态完善画像

### 2.3 五维度对推荐的影响

| 维度 | 影响选校 | 影响选专业 | 影响选城市 |
|------|---------|----------|----------|
| 基础信息 | 位次筛选核心依据 | 科类/选科限制 | — |
| 家庭维度 | 学费筛选（中外合办/民办） | 家庭资源方向 | 就业地偏好 |
| 性格维度 | — | 专业适配度核心 | 城市氛围偏好 |
| 能力维度 | — | 学科匹配 | — |
| 价值观维度 | — | 职业路径匹配 | 距离/城市层级 |

### 4.3 推荐引擎核心算法

```
输入：用户五维画像
输出：冲/稳/保院校列表 + 适配度评分

Step 1 · 位次换算
  当年位次 → 通过"位次等效换算"映射到历年等效位次
  公式：等效位次 = 当年位次 × (历年计划数 / 当年计划数)
  修正因素：试卷难度系数、批次线变化

Step 2 · 院校初筛
  以等效位次为中心，按冲/稳/保区间筛选：
  · 冲：历年录取最低位次 > 等效位次 × 0.85（有希望但有风险）
  · 稳：历年录取最低位次 ≈ 等效位次 × 1.0~1.2（较稳妥）
  · 保：历年录取最低位次 > 等效位次 × 1.3（基本稳妥）
  叠加硬性过滤：省份、科类、选科、体检限制、学费区间

Step 3 · 五维适配度评分
  对每所候选院校/专业计算综合适配度：
  Score = W1×基础匹配 + W2×家庭匹配 + W3×性格匹配
        + W4×能力匹配 + W5×价值观匹配
  各维度权重由用户画像完整度动态调整：
  · 仅填基础信息 → W1=1.0, 其余=0
  · 填写全部五维 → 使用默认权重（可让用户微调）

Step 4 · 排序与输出
  按 冲/稳/保 分组，组内按适配度降序排列
  输出结构化推荐结果 + 每所院校的推荐理由数据
```

### 4.4 LLM编排层设计

LLM不参与核心计算，作为"理解和表达"层：

**场景1：AI志愿顾问对话**
- System Prompt：角色为资深高考志愿规划师
- 注入用户画像摘要（五维数据）+ 当前推荐结果
- Tools（函数调用）：query_university、query_major、calc_probability、compare_universities、get_employment_data
- 约束：所有数据引用必须来自工具返回，不得编造分数线/录取率，必须标注"仅供参考"

**场景2：推荐理由生成**
- 引擎输出结构化数据 → LLM生成自然语言推荐解释

**场景3：深度分析报告**
- 五维画像 + 推荐结果 + 职业数据 → LLM生成分析长文 → PDF渲染

### 4.5 高并发设计（高考季）

| 策略 | 具体措施 |
|------|---------|
| 读缓存 | 院校/专业/分数线等准静态数据全量缓存到Redis，命中率>95% |
| LLM限流 | 免费用户每日3次对话，付费用户排队优先，防止LLM成本失控 |
| 异步生成 | 深度报告异步生成，完成后推送通知，不阻塞用户操作 |
| 静态化 | 院校详情页预渲染为静态页，CDN分发 |
| 弹性扩容 | 容器化部署，设置HPA自动扩缩容 |

## 5. 数据体系

### 5.1 数据资产四层结构

**Layer 1 · 基础数据库（准静态，年度更新）**
- 院校库：3000+院校，含985/211/双一流/民办标签
- 专业库：800+本科专业，含学科评估/课程/就业
- 省份规则库：31省高考模式、批次设置、投档规则
- 职业库：行业→岗位→薪资→发展路径映射

**Layer 2 · 核心录取数据（年度更新，最核心资产）**
- 历年分数线：各校×各专业×各省，近3-5年
- 录取最低分/平均分/最高分 + 对应位次（一分一段表）
- 招生计划数 + 实际录取数（含扩招/缩招）

**Layer 3 · 用户行为数据（实时写入，持续增长）**
- 五维画像、行为轨迹、志愿方案、付费记录

**Layer 4 · 增强数据（可选，提升竞争力）**
- 就业数据、考研/出国率、校友评价、行业趋势

### 5.2 数据采集策略

| 数据来源 | 采集方式 | 更新频率 | 难度 |
|---------|---------|---------|------|
| 阳光高考网 | 结构化爬虫 | 年度(5-6月) | ★★★ |
| 各省教育考试院(31站) | 结构化爬虫 | 年度(6-7月) | ★★★★ |
| 各校本科招生网(2000+站) | 定向爬虫 | 年度 | ★★★ |
| 一分一段表 | 爬虫+人工补录 | 年度(6月) | ★★ |
| 就业质量报告 | PDF解析+人工录入 | 年度(12-1月) | ★★★ |
| 学科评估结果 | 人工整理 | 4年一次 | ★ |

### 5.4 数据质量保障

| 风险 | 应对措施 |
|------|---------|
| 爬取数据不准确 | 多源交叉验证：同一院校数据从阳光高考+学校官网+省考试院三方比对 |
| 年度数据缺失 | 新一年数据未出时，用最近3年加权均值做兜底预测，标注"预测数据" |
| 格式不统一 | 31省数据格式差异大，建立统一清洗管线，各省配置独立解析规则 |
| 人工录入错误 | 关键字段双人录入比对，异常值自动报警（某校某年分数线突变>30分） |
| 数据时效过期 | 建立数据新鲜度标签，超过2年数据降权，所有推荐结果标注数据年份 |

### 5.5 数据合规与隐私

| 数据类型 | 处理策略 |
|---------|---------|
| 家庭收入 | 存储为区间（如"20-50万"），不存精确值 |
| 社交能力 | 存储为评分等级，不存原始自评文本 |
| 对话记录 | 加密存储，用户可删除，保留期限≤1年 |
| 五维画像 | 用户可随时导出/删除全部个人数据 |
| 支付信息 | 不存储，通过微信/支付宝官方SDK处理 |

**合规要求**：
- 隐私政策明确告知数据用途
- 用户注册时明确授权
- 数据不出境（国内云服务部署）
- 未成年人数据保护（大部分用户为18岁考生）
- 符合《个人信息保护法》《未成年人保护法》

核心定位：用AI把"万元级人工咨询"的深度，做到"百元级产品"的价格。

- 合计：¥93-130万

**结论**：首年大概率微亏或持平，核心目标是跑通产品+积累口碑。第二年用户增长至15-20万注册，付费率提升至12%，可盈利。

## 7. 风险分析

| 中 | 法律合规风险 | 较大：未成年人数据保护、推荐结果责任边界 | 中 | 隐私律师审核条款，数据最小化采集，免责声明+不承诺录取 |

| 低 | LLM API成本失控 | 一般：高考季对话量暴增 | 中 | 免费用户严格限次，缓存高频问答，小模型处理简单问题 |
| 低 | 季节性收入不均 | 一般：收入集中在6-7月 | 高 | 延伸场景（考研/春招），offseason做内容运营，控制全年成本 |

## 10. 可行性总结

| 维度 | 评估 | 说明 |
|------|------|------|
| 技术可行性 | 高 | LLM API调用成熟，推荐算法有成熟方案，五维画像+LLM增强是差异化创新点 |
| 数据可行性 | 中高 | 公开数据可获取，但采集清洗工作量大，31省数据格式差异是主要挑战 |
| 市场可行性 | 高 | 1300万考生/年，刚需+高付费意愿，但窗口期极短，时间压力大 |
| 商业可行性 | 中 | 首年大概率微亏，第二年可盈利，季节性收入需要场景延伸来平衡 |
| 竞争可行性 | 中 | 大厂有流量优势，但AI深度应用是窗口期，五维画像+LLM可做差异化壁垒 |
| 合规风险 | 中 | 未成年人数据、推荐责任边界需注意，需要专业法律支持 |

**综合结论**：项目可行，建议尽快启动数据基建（Phase 0），目标在2027年高考季前完成MVP并上线。
